# 한국어 답변 지키기 — language 설정 + 훅 (2026-11-13)

## 문제
사용자: "한글 답변을 대화 중 절반은 안 지킨다". CLAUDE.md 6번 "답변은 항상 한국어" 한 줄만으로는 지켜지지 않음.

## 측정 (이 저장소 Code 세션 대화 기록 14개, 진행 중이던 분석 세션 제외 · `scripts/lang-audit.js`)
| 항목 | 영어 비율 |
|---|---|
| 사용자에게 보인 글 전체 | 22% (92/426), 세션별 0% ~ 70% |
| 턴 마지막 답변 (사용자가 실제로 읽는 보고) | 12% (18/145) |
| Bash 명령 설명 (앱 화면에 보임) | 54% |

## 원인 (메인 분석 → 검증 에이전트가 고침)
- 영어 글 대부분(126개 중 124개)이 **도구 결과 바로 뒤의 짧은 진행 문구** ("Now X…", "Tests written…"). 맥락이 거의 전부 영어(시스템 지침 · 도구 결과 · 알림 · 서브 에이전트 보고)라서 진행 문구가 영어로 샘
- **새면 이어짐**: 앞 글이 영어면 다음 글도 영어일 확률 54%, 앞 글이 한국어면 16%. 그대로 턴 마지막 보고까지 영어가 됨
- 처음 분석은 "하네스 영어 알림(`The user hasn't heard from you…`)이 원인"이라 봤으나, 검증 에이전트가 기준 비율을 비교해 기각: 알림 뒤 영어 전환 11%, 알림 없을 때 17% — 알림 뒤라서 더 많이 새지 않음
- 언어 규칙이 CLAUDE.md 6번 한 줄뿐이고, settings 의 `language` 키는 비어 있었음

## 훅 판정 (`.claude/hooks/lang-check.js`)
- 코드 블록 · 인라인 코드 · 링크 주소 · URL · 경로 · 파일 이름을 뺀 뒤 라틴 글자 20개 미만이면 통과 (코드 위주 · 짧은 답)
- 한글이 한 글자라도 있는 줄만 모아 한글 / (한글 + 라틴) < 0.3 이면 영어 (한글 줄이 없으면 전체로). 검증 지적 반영: 한국어 보고 속 영어 로그 · PR 제목 · 커밋 목록 · 영어 항목 표 줄이 판정을 영어로 끌던 오탐을 없앰
- wrap_up 버튼은 따로: 한글이 없고 라틴 3글자 이상이면 영어 ("Yes, merge")
- 남은 한계: 한 줄 안에 영어 이름이 길게 섞인 한국어("CI 결과: build-and-test success, …")는 영어로 볼 수 있음 → 이름은 백틱으로 (CLAUDE.md 6번)
- `stop_hook_active`(이미 다시 쓰는 중) · 빈 글 · 깨진 입력은 통과 → 무한 반복 없음 (Claude Code 도 연속 차단 8회 상한)
- 한계: 사용자에게 영어 원문과 한국어 다시 쓰기가 둘 다 보임. 턴 중간 진행 문구는 훅이 못 봄 (A · E 로 줄임)
