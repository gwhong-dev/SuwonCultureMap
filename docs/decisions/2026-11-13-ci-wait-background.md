# CI 기다리기 — 알림 대신 백그라운드 `gh pr checks --watch` (2026-11-13)

## 문제

11/13 분기 3개(#260 · #261 · #262)로 병렬 개발할 때, #260 · #261 이 **CI 4개 모두 통과 · 충돌 없음(CLEAN)** 인 채로 멈춰 있었다. 사용자가 작업소(세션)를 새로 만들어도 같은 일이 반복됐다.

## 원인

| # | 무엇이 | 근거 |
|---|---|---|
| ① | 분기 · 메인은 PR 을 올린 뒤 "CI 끝 알림이 오면 머지" 하고 턴을 끝냈다 | CLAUDE.md 4번 6 (옛 문구): "CI 끝 알림이 오면 … 바로 머지", "결과는 알림으로 옴" |
| ② | 데스크톱 앱 Code 탭의 Auto-fix 는 CI **실패** · 충돌 · 리뷰 댓글만 알린다. 통과는 알리지 않는다 | Auto-fix 안내 문구 "watching … for CI failures, merge conflicts, and review comments" |
| ③ | 그래서 깨워 줄 다른 일(검증 에이전트 완료 등)이 남지 않은 세션은 영원히 기다린다 | #262 는 검증 에이전트 완료 알림에 우연히 깨어 계속됨, #259 는 메인이 백그라운드 `--watch` 를 걸어 계속됨 |

옛 규칙은 클라우드 세션(GitHub 구독 알림이 옴) 기준이었고, 11/12 로컬 Code 탭으로 옮기면서 전제가 깨졌다.

## 결정 (사용자 11/13 "A")

PR push 직후 CI 대기 명령을 **백그라운드 명령**으로 건다. 명령이 끝나면 하네스가 세션을 깨우고, 그때 결과를 보고 머지한다. 머지 뒤 Deploy 대기도 같은 방식. 메인 · 분기 모두 적용.

- 검증(#263 '보완 후 통과')이 잡은 함정을 명령에 반영: push 직후 첫 확인이 **이전 커밋 결과**로 끝남 → 먼저 `sleep` + PR head 가 지금 커밋인지 비교 / `Docker 이미지 빌드` 는 빌드 + 테스트 뒤에야 목록에 생김 → 그 줄이 있고 pending 이 없을 때만 끝 (실패가 보이면 바로 끝) / 15분 넘으면 다시 건다 / Deploy 는 머지 커밋 SHA 로 골라 기다림 (`gh run list -L1` 은 이전 배포를 잡음)
- 분기가 앱 기본 안내("CI 직접 조회 금지")를 이유로 대기 명령을 거부한 일(#261) → 이 규칙이 우선이라고 명시하고, 그래도 못 걸면 메인이 대신 걸어 결과를 보내 줌
- 처음엔 `gh pr checks <N> --watch` 하나로 정했으나, 이 PR(#263) 자체에서 push 직후 실행하자 검사가 아직 등록되지 않아 "no checks reported" 로 **바로 끝나는** 함정을 확인 → 검사가 생기고 pending 이 없어질 때까지 20초 간격으로 도는 반복 명령(최대 15분)으로 바꿈 (명령은 CLAUDE.md 4번 6)

## 버린 안

- B: A + 메인이 분기 메모에 "CI 기다림" 이 보이면 직접 `gh pr checks` 확인 — 사용자가 A 만 고름 (메인이 매번 대신 확인하는 일을 늘리지 않음)
- 자동 머지(auto-merge) 켜기 — CLAUDE.md 7번이 금지 (M · L 검증 댓글 · L 사용자 승인 뒤에만 머지해야 함)
- 일정 시간 뒤 점검 예약 — CI 는 2~3분인데 예약은 늦거나 헛돌고, 로컬 앱엔 `send_later` 가 없음
