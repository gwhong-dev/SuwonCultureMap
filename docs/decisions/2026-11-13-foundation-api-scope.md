## 결정

행사(29_EV) 외에 **랜드마크 · 상설 3건 · 읽을거리**를 넣고, **교육은 뺀다**. 수원바이블의 중심은 자주 바뀌는 행사(팝업 등)라서, 랜드마크는 행사 지도에 섞지 않고 별도 **'명소' 페이지**로 둔다.

|---|---|---|---|
| 랜드마크 | 59_C 수원화성 시설물 (48) · 63_C 화성행궁 시설물 (27) | 넣음. 75_C 테마체험(1)은 59_C 성신사와 같은 내용이라 제외 | 별도 '명소' 페이지. 메인 지도에서는 체크박스를 켜면 함께 표시 |

## 데이터 주의

- **좌표가 뒤바뀌어 있음**: lat 칸에 경도(127.x), lng 칸에 위도(37.x). → 값 범위(위도 33~39 · 경도 124~132)로 판정해 바로잡음. 재단이 고쳐도 그대로 맞음 (`LandmarkParser.coordinates`)
- **좌표 없는 곳 10건** (59_C 7: 북옹성 · 용연 · 용도 · 성신사 · 미복원 동쪽 성벽 · 미복원 서쪽 성벽 · 북은구 / 63_C 3: 취병 · 화성행궁 물길 · 삼국시대 석실묘) → 인스타 행사에 쓰는 카카오 장소 검색(`PlaceGeocoder`)으로 보충, 안 잡히면 좌표 null (목록에만, 마커 생략)
  - 11/13 실제 검색: 이름 그대로 "용연" 1곳, "수원화성 성신사" 1곳만 잡힘. 나머지 8곳은 카카오에 없음 → null
- 상설(73 · 74)은 날짜 칸(sdate · edate)이 없고 "연중(월 휴연)" 같은 문장만 있음 → 메인의 진행 중 · 곧 종료 · 달력 계산에 넣지 않음
- 상설 중 수원행차 · 스탬프 투어는 좌표 없음. 장소 글자로 잡음: 수원행차 = 연무대, 스탬프 투어 = 대표 1곳(화성행궁)
- 시설물 본문(description)은 HTML 이 이중 이스케이프된 국문 + 영문. 첫머리에 창건 · 복원 연도, 보물 지정. 영문 단락은 `<div class="line">` 구분선 뒤
- **코드마다 인증키가 다름** (9개). 환경변수로 받고 값은 노션 비공개 페이지에만. 테스트 키(test)는 코드별 최대 3건만 응답
- 교육정보 코드는 30_ED (매뉴얼의 30_EV 로 부르면 행사 데이터가 옴)
- 읽을거리 번역 · 영상화는 재단 저작물의 2차 가공이라 재단 회신 뒤 진행. 그 전에는 한국어 원문 + 원문 링크까지만

## 불러오는 방법 (① 에서 확정한 것)

- **저장**: `Event` 와 분리한 `landmark` 테이블 (V10). 날짜가 없어 행사 합치기 · 진행 중 계산과 섞이면 안 됨
  - 여러 출처 공용: `source`(`SWCF_FORTRESS` · `SWCF_PALACE`, 나중에 `SWDB_SPACE` 수원문화DB 문화예술공간 · `MANUAL` 직접 추가) + `source_key`(재단 idx) UNIQUE
  - 재동기화 때 지우고 다시 넣지 않고 갱신 → **id 유지** (② 찜이 id 를 가리킴). 응답에서 빠진 곳도 지우지 않고 `last_seen_at` 이 멈춤
  - 칸: 이름 · 종류(수원화성/화성행궁) · 위도 · 경도(null 허용) · `coord_source`(API/KAKAO) · 창건 · 복원 한 줄(`history`) · 비공개 · 대표 사진 원본 주소(https 로 바꿈, 파일은 안 받음) · 원문 링크 · 국문 본문(HTML 제거) · 게시일 · 만든 · 바뀐 · 마지막으로 본 시각
  - 읽을거리는 나중에 `Story` 테이블 (④)
- **동기화**: 하루 1회, 행사 자동 동기화(06 · 18시)에 같이 돌되 마지막 성공이 20시간 안이면 건너뜀. 명소가 없는 DB 는 앱이 뜬 직후에도 1회. 이력은 `sync_log` 의 `LANDMARK`
  - 한 코드가 실패해도 다른 코드는 저장, 이력은 실패(코드 + 예외 종류만 — 호출 주소에 키가 있어 메시지는 남기지 않음) → 다음 자동 동기화에서 다시
  - 카카오로 한 번 보충한 좌표는 다시 검색하지 않음. 좌표 없는 곳만 매번 다시 시도 (하루 8곳 × 최대 2회)
  - 재단이 좌표를 지우거나 범위 밖 값으로 바꾸면 옛 재단 좌표(API)를 비우고 다시 보충 (옛 좌표를 계속 찍지 않게 — PR #254 검증 지적)
  - 보충 좌표 인정 기준: 결과 이름이 검색어와 **정확히 같고**, 수원화성 · 화성행궁 둘레 범위 안. "수원화성 북옹성" 검색에 "수원화성" 자체가 나와도 인정하지 않음 (틀린 위치보다 안 찍는 쪽)
- **인증키**: 59_C = `swcf.api.key.facility` (`SWCF_API_KEY_FACILITY`), 63_C = `swcf.api.key.palace-facility` (`SWCF_API_KEY_PALACE_FACILITY`). 비어 있으면 그 코드를 받지 않음 (앱은 뜸). 키가 하나만 있으면 없는 코드는 실패가 아니라 '건너뜀'으로 세고 이력은 성공 (매번 실패로 하루 두 번 받는 것을 막음)
- 상설은 idx 허용 목록(67 · 224 · 223)만 저장해 운영 중단 데이터 차단 (③)
- 순서: ① landmark + 59_C · 63_C 동기화 + 시험 (**L** — entity · migration · 설정 경로라 CLAUDE.md 기준으로 원안 M 에서 올림) → ② 명소 페이지 + 메인 지도 체크박스 (M) → ③ 상설 3건 (S) → ④ 수원 이야기 (M, 재단 회신 뒤)
- 나중에: 수원문화DB '문화예술공간'(공연장 · 미술관 등 약 104곳)과 직접 추가 명소(경기도서관 등)도 같은 테이블에

## 버린 안

- 랜드마크를 행사(`event`) 테이블에 종류 칸으로 섞기 → 날짜 없는 행이 진행 중 · 달력 · 합치기 계산에 끼어듦
- 재동기화 때 지우고 다시 넣기 → id 가 바뀌어 찜이 끊김
- 좌표 없는 곳을 수원화성 대표 좌표로 찍기 → 틀린 위치가 지도에 뜸
