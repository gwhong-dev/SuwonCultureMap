## 3. 버린 안

- **채팅에서 기획서(spec) 작성 → Code 가 읽기**: 채팅이 코드를 못 보고 써서 Code 가 다시 묻게 됨 → 루프가 남음. 큰 방향 고민만 채팅에서 하고, 계획은 항상 Code 가 다시 세움
- **등급 2단계(일반 · L)**: 검증 대상이 줄지만 M 검증이 실제 결함을 계속 찾고 있어 보류
- **클라우드 Code 로 밖에서 작업**: DB · 로그인 확인 불가 → 다시 사용자 중계
- **원격 조종(집 PC 세션을 밖에서 조작)**: 집 PC 를 항상 켜 둬야 함

공식 문서 사실 확인 + 설계 검토 결과 정정 · 반영한 것:

| 지적 | 반영 |
|---|---|
| CLAUDE.md 는 지침이지 강제 장치가 아님 (공식 문서) | 꼭 지켜야 하는 것(push 확인 · 비밀값 검사 · L 머지 차단)은 훅 · CI 로 강제 — 전환 5단계 |
| Stop 훅은 세션 끝이 아니라 응답마다 실행됨 | 세션 시작 시 경고(SessionStart) 방식으로 설계 |
| CLAUDE.md 만 고치면 원본이 하나가 안 됨 (메모리 · 전역 CLAUDE.md · 클라우드 설정에 옛 규칙) | CLAUDE.md 맨 위 우선 선언 + claude.ai 메모리 작업 규칙 줄을 포인터로 교체 + 프로젝트 지침 축소 |
| USB 를 작업 폴더로 쓰면 경로가 다르고 `.git` 손상 위험 | 각 PC 내장 디스크 clone 으로 전환 — 전환 4단계 |
| 공개 저장소에 캡처를 자동 저장하면 개인정보 · 토큰 노출 | 고른 것만 · 가림 · 300KB 이하, 작업 중 캡처는 PR 댓글 |
| "채팅이 PC 파일을 읽는다"는 공식 근거 없음 | 채팅은 GitHub 연동으로 저장소 파일을 읽는 방식으로 (프로젝트에 저장소 연결 필요, PNG 캡처가 연동으로 읽히는지는 연결 후 확인) |
