# 대화 길이 훅 — 긴 세션을 기계로 막기 (2026-11-13)

## 문제

- CLAUDE.md 8번은 "메인 대화가 아주 길어졌을 때" 새 세션으로 넘기라고만 적혀 있었다. 숫자가 없어서 Claude 가 감으로 판단했고, Claude 는 지금 대화 크기를 볼 수 없다.
- 사용자가 몇 주째 "대화를 길게 끌지 말 것"을 요청했지만 고쳐지지 않았다. 지난 세션 40개 중 20만 토큰 넘은 것이 다수, 최대 66만.
- 비용은 마지막 크기가 아니라 **턴마다 다시 읽는 양의 합**이다. 뒤쪽 턴일수록 비싸다.

## 실측 (11/13, 이 PC 대화 기록)

| 항목 | 값 |
|---|---|
| 새 세션 첫 턴 크기 (기본 지침 · 도구 목록) | 약 10만 (그중 약 6만은 이미 캐시, 새로 읽는 양 약 4만) |
| 지난 세션 마지막 크기 | 20만~66만 |
| 예: 40턴 동안 10만 → 66만 | 한 세션 합계 약 1,550만 / 20턴씩 둘로 나누면 약 990만 + 넘기기 약 10만 → 약 35% 절약 |

## 결정

- 훅 `.claude/hooks/session-length.js` — 대화 기록(transcript)의 마지막 응답 사용량(input + cache_creation + cache_read)으로 크기를 잰다
  - **20만 이상 (UserPromptSubmit)**: 질문마다 "작업 단계가 끝나면 넘기기" 안내를 Claude 에게 보여 줌. 막지 않음
  - **30만 이상 (Stop)**: 30만을 처음 넘은 뒤 `start_session`(새 메인 세션)을 부르지 않았으면 턴을 못 끝내게 막음. 같은 턴 재시도(`stop_hook_active`)는 통과 → 무한 반복 없음, 다음 턴에 다시 막음
  - 분기 세션은 새 세션을 만들지 않으므로 답변에 `[분기 막힘] 대화 길이 초과` 를 쓰면 넘긴 것으로 침 → 이후 턴마다 다시 막지 않음 (검증 지적: 안 그러면 CI 알림 턴까지 매번 막혀 30만+ 턴이 더 생김)
  - `hand_off_to_session` 은 넘기기로 치지 않음 — 지금 작업만 떼어 내고 메인 대화는 그대로 길게 남음 (검증 지적)
- 기준 숫자는 CLAUDE.md 8번에도 적어 "아주 길어졌을 때"의 애매함을 없앰

## 버린 안

| 안 | 버린 이유 |
|---|---|
| CLAUDE.md 에 숫자만 적기 | Claude 가 크기를 볼 수 없어 지킬 수 없음 — 기존 실패 원인 그대로 |
| 20만에서 바로 차단 | 기능 개발 중간에 넘기면 코드를 다시 읽어 오히려 손해 → 20만은 안내만 |
| 턴 수로 재기 | 턴마다 늘어나는 양(파일 읽기 · 캡처)이 크게 달라 기준이 안 맞음 |
| 자동 압축(compact) 기준 낮추기 | 요약 품질에 기대야 하고, 인수인계 형식 · PROGRESS.md 확인 같은 절차가 빠짐 |

## 한계

- 서브 에이전트 기록(`isSidechain`)은 빼고 잼 (메인 대화 크기만)
- 30만 전에 만든 카드(분기 시작 등)는 넘기기로 치지 않음
- 30만 뒤 `start_session` 을 한 번 부르면(거절 · 실패 · 사용자가 "여기서 계속" 포함) 그 세션은 다시 막지 않음 — 사용자 선택을 존중
- `stop_hook_active` 는 Stop 훅들이 함께 씀 → 이 훅이 막아 다시 쓴 답변은 `lang-check.js` 가 다시 보지 않음 (영어로 다시 쓸 가능성은 낮아 둠)
- 사용량 기록이 쌓이면 기준 숫자를 다시 정할 수 있음
