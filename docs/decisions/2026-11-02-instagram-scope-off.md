# 인스타그램 수집 중단 결정

- 결정일: 2026-11-02
- 결정한 사람: 사용자(운영자)
- 상태: **대체됨** → [수집 재개 결정 (수원 공식 계정만)](2026-11-02-instagram-resume-official.md). 2026-11-01의 "Meta도 허락을 기다리지 않고 먼저 출시" 결정을 대체한다. 재단 데이터 방침은 바뀌지 않는다.

## 배경

수원바이블은 Business Discovery API로 공공기관 · 문화시설의 공개 인스타그램 게시물을 받아, 캡션에서 행사 정보를 뽑아 저장하고 공개 지도에 표시했다.

Meta Platform Terms를 다시 읽었지만, 남의 공개 게시물에서 행사 정보를 뽑아 저장하고 공개 지도에 표시하는 용도가 허용되는지 명시된 곳을 찾지 못했다. 금지 조항을 찾은 것이 아니라 **허용 근거를 찾지 못한 것**이다.

## 걸린 조항

| 조항 | 걸리는 이유 |
|---|---|
| 3.a.viii | 허용 목적 밖의 처리 금지. 이 용도가 허용 목적에 들어가는지 확인되지 않음 |
| 3.c | 제3자 공유 조건. 공개 지도 표시가 여기에 해당하는지 확인되지 않음 |
| 접근 수준 (Standard / Advanced) | Advanced에는 앱 심사와 비즈니스 인증이 필요함. 현재는 앱 심사를 통과하지 않음 |

## 문의 시도와 결과

- Meta 개발자 지원(Direct Support)은 이 계정에서 접근할 수 없어, 공식 답을 받지 못했다.

## 결정

공식 답을 받을 때까지 인스타 수집을 끈다. 코드는 지우지 않고 다시 켤 수 있게 둔다.

| 항목 | 내용 |
|---|---|
| 스위치 | `instagram.sync.enabled` (환경변수 `INSTAGRAM_SYNC_ENABLED`, 기본값 `false`) |
| 수집 | 꺼져 있으면 스케줄러와 수동 API 모두 Meta API를 호출하지 않음 |
| 표시 | `/api/events`, 찜 목록, 찜 추가, 캘린더, 합치기 미리보기(개발 전용) 어디로도 인스타 행사를 내보내지 않음 |
| 스위치 밖 | 손으로 실행하는 `scripts/instagram-peek.cmd`는 앱을 거치지 않고 Meta API를 직접 호출함. 다시 켜는 조건을 충족하기 전에는 실행하지 않음 |
| 영향 없음 | 재단 동기화 · 합치기. 재단 행사가 있는 묶음은 재단이 대표라서 재단 행사는 그대로 보임 |
| 저장된 데이터 | 이 결정으로 자동 삭제하지 않음. `scripts/instagram-data-delete.sql`을 사용자 승인 후 실행 |
| 삭제 후 남는 것 | 매일 백업에 최대 14일, 서버 로그의 처리 기록은 용량 제한으로 지워질 때까지 |

스위치는 **서버에 반영해야 효력이 생긴다.** 반영 전까지는 운영 사이트의 수집과 표시가 멈추지 않는다.

## 다시 켜는 조건

아래 중 하나를 충족하고, 그 근거를 이 문서에 추가한 뒤에 켠다.

1. Meta의 서면 허용 답변
2. 앱 심사 통과

켜는 순서:

1. 저장된 옛 데이터가 남아 있으면 `scripts/instagram-data-delete.sql`을 먼저 실행한다. 스위치를 켜는 즉시 옛 행이 다시 보이는데, 그 게시물은 그동안 지워졌을 수 있다.
2. 개인정보처리방침 10번과 서비스 안내의 정보 출처 문구를 되돌린다.
3. 스위치를 켜고 새로 수집한다. 토큰이 만료됐으면 먼저 다시 교환한다.

## 광고 도입 시 주의

맞춤 광고에 인스타에서 유래한 데이터를 넘기지 않는다.

- 3.a.iv: 판매 금지
- 3.a.v: 프로필 구축 금지

수집을 다시 켠 뒤에도 적용한다. 삭제 스크립트를 실행하기 전에는 저장된 데이터에도 적용한다.
