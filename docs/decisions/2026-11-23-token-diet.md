# 개발 과정 토큰 줄이기 (2026-11-23)

## 왜
같은 계정의 다른 저장소(photo-video-manager)에서 대화 기록을 집계해 보니 짐작과 달리 "긴 대화를 말할 때마다 다시 읽는 값"이 비용 대부분이었다. 그 저장소가 정리한 `docs/개발-토큰-점검-가이드.md` 를 이 저장소에도 그대로 적용한다.

## 무엇을 쟀나
점검 스크립트(가이드 9절)는 이 PC 에서 다시 돌리지 않고, 다른 PC 에서 잰 가이드 0절 숫자를 근거로 쓴다 (2026-11-23, 이 저장소 대화 기록 전체). 토큰은 API 요금 비율(캐시 읽기 0.1 · 캐시 쓰기 1.25 · 출력 5 · 입력 1)로 가중한 어림값.

| 어디서 | 몫 | 판정 기준(가이드 2절) |
|---|---|---|
| 대화 다시 읽기(캐시 읽기) | **75%** | — |
| 대화가 20만 토큰을 넘은 턴에서 나온 비용 | **59%** | 30% 넘음 → ① 대화 길이 상한 |
| 에이전트(검증 · 조사) 몫 | 8% | 15% 넘어야 ⑤ → 해당 없음 |

함께 본 이 저장소의 앞선 실측 ([2026-11-13 대화 길이 훅](2026-11-13-session-length-hook.md)):

| 항목 | 값 | 판정 |
|---|---|---|
| 세션 시작 바탕(기본 지침 · 도구 목록) | 약 10만 토큰 | 6만 넘음 → ③ 시작 바탕 줄이기 |
| 지난 세션 마지막 크기 | 20만~66만 | 50만 넘음 → ② 주제마다 새 세션 |

11/13 훅(20만 경고 · 30만 차단)을 넣은 뒤에도 20만 넘은 턴이 59% 다. 30만 차단 전까지의 20만~30만 구간이 그대로 비싸고, 경고는 막지 않기 때문이다.

## 고른 처방
1. **① 대화 길이 상한 20만**: `.claude/settings.json` 에 `env.CLAUDE_CODE_AUTO_COMPACT_WINDOW = "200000"` (Claude Code 공식 설정, 자동 요약 창 크기). 20만 전에 대화가 자동으로 요약돼 그 뒤 턴이 다시 읽는 양이 줄어든다
2. **② 메인 교체 기준 15만**: 훅 `session-length.js` 경고를 20만 → **15만**, 차단을 30만 → **20만**으로 낮춤
   - 평소엔 자동 요약이 20만 전에 일어나 차단까지 가지 않는다. 경고(15만)를 보고 하던 PR 끝에 새 세션으로 넘기는 것이 기본 길
   - 차단(20만)은 자동 요약 설정이 안 먹을 때(폴더 신뢰 전 · 다른 도구에서 연 경우)의 안전망
   - 시험 1건 추가: 경고 15만 < 차단 20만 = 자동 요약 창 값이 서로 어긋나지 않게 고정
3. **③ 안 쓰는 플러그인 끄기**: `enabledPlugins` 에서 `superpowers` · `adhd-study-coach` · `learn-with-coursera` · `pdf-viewer` 를 `false` (claude.ai 에서 동기화된 플러그인은 `이름@synced`). 다른 PC 에 공식 마켓에서 깔렸을 수 있는 `superpowers` · `context7` 도 같이 끔
   - 이 PC 에서 `claude plugin list` 로 임시 폴더 시험: 프로젝트 설정의 `이름@synced: false` 가 실제로 "disabled" 로 바뀌는 것 확인
   - superpowers 는 세션마다 긴 안내를 넣고, 이 저장소는 CLAUDE.md 4번에 자체 개발 절차가 있어 겹친다
   - 남김: `code-review` · `code-simplifier` (검토 도구), 계정 스킬(`suwon-artifact-tree` 등 — CLAUDE.md 4-3 에서 씀)
   - 계정 연결 도구(Canva · Figma · Google Drive 등)는 저장소 설정으로 못 끈다 → 사용자가 앱에서 끔 (Notion 은 노션 정리에 써서 남길지 사용자 판단)

| 자동 요약 없이 훅 차단만 20만으로 | 차단은 턴 끝에서만 막아서, 한 턴 안의 긴 작업은 20만을 넘어도 계속 비쌈. 자동 요약은 턴 중간에도 줄여 줌 |
| 11/13 결정의 "자동 압축 기준 낮추기는 버림" 유지 | 그때 걱정(요약 품질 · 인수인계 절차가 빠짐)은 남아 있지만 59% 라는 숫자가 더 크다. 대신 15만 경고로 정상 인수인계를 먼저 하고, 자동 요약은 놓쳤을 때의 상한으로만 둔다. 요약 전에 결정 · 다음 할 일을 저장소 파일에 적는 규칙을 CLAUDE.md 8번에 넣음 |

## 확인할 것 (머지 뒤)
- 새 세션에서 `get_usage`: 자동 요약 기준이 20만 근처인지, 시작 바탕이 10만보다 줄었는지
- 프로젝트 설정의 `env` 는 사용자가 폴더를 신뢰한 뒤 적용된다. 안 바뀌면 같은 값을 사용자 설정(`%USERPROFILE%\.claude\settings.json`)에 넣을지 사용자에게 묻는다
- 1~2주 뒤 가이드 9절 스크립트를 다시 돌려 "20만 넘은 턴 몫" 59% 가 줄었는지 비교, 그때 ④ 도 판정
