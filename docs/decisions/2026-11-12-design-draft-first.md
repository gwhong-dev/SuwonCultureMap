# 화면 시안 먼저 — Claude Design 캔버스 (2026-11-12)

## 결정

화면이 바뀌는 작업은 개발 전에 **Claude Design 캔버스**에 시안을 만들고, 사용자가 눈으로 보고 정한 뒤 개발한다. 앞으로 항상. 규칙은 `CLAUDE.md` 4-2.

- 시안 = 사용자가 캔버스에서 **직접 옮기고 고칠 수 있는 아트보드**
- 사용자가 고친 최종본이 개발 기준
- 확정된 작업부터 분기 세션으로 병렬 개발

## 왜

- 사용자가 직접 화면을 쓰며 할 일 16개를 적었다(문서 "수원문화지도-해야할일"). 대부분 배치 · 카드 내용 · 넘기기 동작처럼 **보고 정할** 작업이다
- 그동안은 시안이 코드 · PR 캡처로 나와, 사용자는 글로만 고칠 점을 말할 수 있었다. 11/11 에는 시안 확인 전에 PR 이 머지된 일도 있었다(#202 · #203)
- 캔버스에서 사용자가 직접 옮기면 말로 설명하는 단계가 줄고, 확정본이 그대로 개발 기준이 된다

## 버린 안

| 안 | 버린 이유 |
|---|---|
| 코드로 먼저 만들고 PR 캡처로 확인 | 고칠 때마다 코드 수정 · CI 를 다시 돈다. 사용자가 직접 손댈 수 없다 |
| 이미지 한 장 시안 | 보기만 되고 사용자가 옮기거나 고칠 수 없다 |
| 모든 작업에 시안 | 원래 모양으로 되돌리는 버그 · 키보드 동작은 화면이 안 바뀐다 → 생략, 애매하면 만든다 |

## 분기에 시안을 넘기는 방법 (검증 지적 반영)

- 클라우드 분기는 비공개 claude.ai 캔버스를 못 열 수 있다 → 사용자가 "확정"하면 메인이 최종본 값을 `docs/design/YYYY-MM-DD-주제.md` 에 옮겨 적고, 분기 지시서에는 그 문서 경로를 넣는다
- 확정 시안대로 만든 개발 PR 은 보통 절차대로 머지한다. 시안과 달라지거나 시안에 없던 화면이 생기면 PR 까지만
