# 데이터 출처 추가: 수원문화DB 행사정보 크롤링 (2026-11-13)

## 결정
- 수원문화재단 "수원문화DB" 행사정보를 크롤링해서 행사 데이터에 추가한다.
- 이유: 재단 API(29_EV)에 없는 **민간 공간 · 개인 · 단체 행사**(소규모 전시 · 공연)가 많다. 11/13 기준 행사정보 총 328건.
- 재사용 허락: robots.txt 는 접근 규칙일 뿐 재사용 허락은 아니다. 사용자 판단(11/13): 비상업 · 홍보 목적이라 **설정이 끝나면 지도에 올린다**. 운영은 스위치 `SWDB_SYNC_ENABLED` 로 켜고, 재단 문의 메일에 "수원문화DB 활용"을 함께 묻는다.

## 수집 대상 (robots.txt 허용)
| 페이지 | 주소 | 용도 |
|---|---|---|
| 행사정보 목록 | `https://www.swcf.or.kr/swdb/?p=15&page=N` | 전체 목록 (페이지 번호로 넘김) |
| 행사정보 상세 | `https://www.swcf.or.kr/swdb/?p=15_view&reqIdx=<ID>&page=1` | 기간 · 장소 · 분류 |
| 지원사업 행사정보 | `https://www.swcf.or.kr/swdb/?p=45&schDate=YYYY-MM-DD` | p=15 의 일부로 보임 — 쓰지 않음 |
| (나중) 문화예술공간 | `https://www.swcf.or.kr/swdb/?p=8` | '명소' 페이지 후보 (아래 "공간 기준") |

목록 항목: 대표 이미지 · 분류(전시/공연/교육/행사/기타) · 행사명 · 장소(주소) · 날짜(시작일) · 짧은 소개. 고유 키: `reqIdx` (앞 14자리 = 등록 시각).

## robots.txt (2026-11-13 확인, https://www.swcf.or.kr/robots.txt)
```
User-agent: *
Disallow: /cmsMng/
Disallow: /*mode=search*
Disallow: /*searchTxt=*
Disallow: /*searchText=*

User-agent: Yeti
Disallow: /swdb/?p=39_view&reqIdx=202212261759457496
```
- `searchTxt` · `searchText` · `mode=search` 가 들어간 **검색 주소는 쓰지 않는다.** 목록 + `page=` 만 쓴다.
- `Yeti`(네이버 로봇) 규칙은 동행공간 1페이지라 무관.

## 수집 규칙
1. 하루 1회(예약 동기화 06 · 18시 중 마지막 실행 20시간 뒤 첫 번), 요청 사이 1.5초 쉼. User-Agent `SuwonCultureMap/1.0 (+https://suwonbible.com)`.
2. 저장: 제목 · 기간 · 시간 · 장소 · 분류 · `reqIdx` · 원문 링크 · 대표 이미지 **원본 주소**.
3. 소개글 전문 · 이미지 파일은 복사하지 않는다(등록자 저작물). **주관단체 및 개인(개인 이름) · 문의처(휴대폰 번호)도 저장하지 않는다**(개인정보).
4. 화면에 "출처: 수원문화DB(수원문화재단)" + "원문 보기" 링크 표시.
5. 재단 API(29_EV) 행사와 겹치면 **무조건 재단 것만** 보여준다 (기존 합치기: 날짜 겹침 + 300m 또는 같은 장소명 + 제목 유사도. 대표 순서 재단 → 인스타 → 수원문화DB).

## 행사 거르기 기준 (DB 에 넣기 전, 11/13 사용자 확정)
| # | 기준 | 처리 |
|---|---|---|
| 1 | 이미 끝난 행사 (종료일 < 오늘) | 저장 안 함 |
| 2 | 제목에 "모집" (참가자 · 강사 · 단체 모집 공고) | 저장 안 함, 상세도 안 읽음 |
| 3 | 수원 밖 주소 · 주소 없음 · 좌표를 못 찾음 | 저장 안 함 |
| 4 | 장소가 여러 곳 / 넓은 범위 | **제외하지 않음** (사용자): 찾은 첫 장소 · 기준 장소에 핀, 카드 장소 줄 `여러 장소 · A 외 N곳` / `수원역 일대(이동형)`, 상세에 "원문에서 꼭 확인" 안내 |
| 5 | 기간 이상 (종료 < 시작, 1년 초과) | 저장 안 함 |
| 6 | 재단 API 와 같은 행사 | 재단 것 우선 (합치기) |

읽는 범위: 목록은 1쪽부터, 한 쪽 전체가 시작일 180일보다 오래되면 멈춤. 상세는 처음 보는 최근 행사와 아직 안 끝난 저장 행사만.

## 좌표
- 주소에서 도로명 · 지번만 떼어 카카오 **주소 검색**(328건 중 97% 가 이 모양) → 수원 안 결과 1건째.
- 주소가 없으면 기존 `PlaceGeocoder`(장소 이름 검색 — 틀린 위치보다 안 찍기). 여러 장소 · 일대 규칙은 수원문화DB 만 따로 (`SwdbPlaceResolver`), 인스타 동작은 그대로.

## 공간(랜드마크) 기준 — 나중 작업용 (11/13 사용자 확정)
문화예술공간 220곳(공공 150 · 민간 70, 2020년 일괄 등록 100곳)을 '명소'로 보여 줄 때:
1. 방 · 대관 공간 제외: 이름에 `회의실 · 강당 · 세미나실 · 다목적 · 강의실 · 교육실 · 체육관 · N층` (67곳)
2. 연습실 제외: 소분류 `연습실` 또는 이름에 `연습실` (10곳)
3. 도서관 제외 (27곳) — **예외: `망포글빛도서관` · `광교푸른숲도서관`** (대형 · 건축물 명소)
4. 운영 확인: 카카오 장소 검색에서 같은 이름이 등록 주소 300m 안에 있으면 표시, 못 찾으면 보류. 한 달에 한 번 다시 확인
5. 수원문화DB 에 없는 명소(**경기도서관** — 경기도 운영이라 미등록)는 "직접 추가 명소" 목록으로
- 남는 곳 104곳 (공연장 38 · 복합문화공간 17 · 공방 16 · 전시장 11 · 미술관 · 화랑 · 박물관 14 · 기타 8)
- "공공 + 기타문화시설 + 기타" 통째 제외 안은 버림 — 수원문화원 · 수원향교 · 경기 상상캠퍼스 · 수원전통문화관이 같이 빠짐
- 명소 화면 · 테이블은 명소 ① ② 작업(재단 59_C · 63_C)과 같은 테이블에 넣는다

## 버린 안
- 장소 여러 곳 · 넓은 범위 행사 제외 → 사용자: 기준 장소에 핀 + 안내가 낫다
- 새 칸(DB 스크립트)으로 안내 저장 → `info` 칸에 안내 글만 넣고 화면이 출처로 구분 (원문 소개글은 저장하지 않으므로 `info` 가 비어 있음)
- 시안 생략: 카드 · 상세는 기존 자리에 글자만 들어감. 확인용 시안은 [명소 · 수원문화DB 시안](https://claude.ai/artifact/YTC4Cy8BgSKZo1LyL2QS9J) ④ · PC ④
