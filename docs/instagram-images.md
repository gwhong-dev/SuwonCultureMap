# 인스타 행사 사진 — 서버 디스크에 저장 (11/9)

> 사용자 결정(11/9): 저장 위치 = **운영 서버 디스크(Docker 볼륨)**, S3 아님. 코드 `InstagramImageStore` · `InstagramImageWebConfig`.

## 왜

Graph API 가 주는 사진 주소(`media_url`)는 서명이 붙은 CDN 주소라 **며칠 뒤 만료**된다. 그대로 저장하면 지도 · 목록 사진이 깨진다 → 받아 두고 우리 주소로 내보낸다.

## 규칙

| 항목 | 정한 것 |
|---|---|
| 어디서 받나 | 수집 응답의 `media_url`(사진 · 묶음 = 첫 장), 동영상은 `thumbnail_url`. **https + `*.cdninstagram.com` · `*.fbcdn.net` 만**, 넘겨주기(redirect) 안 따라감 (다른 주소로 요청을 보내게 만드는 공격 차단) |
| 언제 받나 | 게시물 처리 끝에 **행사(READY)가 1개 이상 나온 글만**. 행사 없는 글 · 공지 사진은 받지 않음. 파일이 이미 있으면 다시 안 받음 |
| 파일 이름 | `{게시물 id}.{jpg\|png\|webp}` — 게시물 id 는 숫자만(검사), 확장자는 응답 종류가 아니라 **파일 앞부분**(JPEG · PNG · WEBP)으로 정함. 같은 글의 행사들이 파일 하나를 같이 씀 |
| 볼륨 경로 | 컨테이너 `/app/images` = 볼륨 `insta-images` (`docker-compose.prod.yml`), 설정 `instagram.image-dir` ← `INSTAGRAM_IMAGE_DIR`. 비어 있으면(로컬 · 시험 기본) 기능 꺼짐 = 전과 같음(사진 없음) |
| 우리 주소 | `/media/insta/{게시물 id}.jpg` (상대 주소, 응답 `imageUrl`). 캐시 7일 · `nosniff`, 사진 확장자만 내보냄(`.part` 등은 404) |
| 크기 제한 | 5MB. `Content-Length` 가 넘거나 받는 중 넘으면 중단 · 임시 파일(`.part`) 삭제. `Content-Type` 이 `image/*` 가 아니면 저장 안 함 |
| 실패하면 | 저장 실패(HTTP 오류 · redirect · 크기 초과 · 이미지 아님 · 시간 초과: 연결 5초 · 응답 15초 · 본문 전체 20초) → **원래 주소 그대로**(만료되면 화면이 사진 칸을 숨김, #132). 허용 도메인이 아닌 주소는 원래 주소도 안 씀(null) |
| 지울 때 | 동기화(`InstagramSyncService.sync`)가 끝날 때마다 — 수집이 꺼져 있어도 — **DB 인스타 행사가 더 쓰지 않는 파일을 삭제**. 행사가 내려가면(`StaleBlockRetirer`) · 지워지면(삭제 요청 · 정리 규칙) 사진도 다음 동기화(최대 12시간) 끝에 같이 지워짐. 처리가 되돌려져 남은 파일 · `.part` 도 이때 지움. 쓰는 목록을 못 읽으면 지우지 않음 |
| 백업 | DB 백업(`backup-db.sh`)에 사진은 넣지 않음. 볼륨이 없어져도 글이 최근 수집 범위(계정당 10개) 안이면 다음 동기화에 다시 받음 |

## 다른 것에 미치는 영향

- **CSP `img-src`**: 지금 CSP 에 `img-src` 가 없어 변화 없음. 나중에 `img-src` 를 두면 우리 주소는 `'self'` 로 충분 (원래 주소로 남은 실패분은 CDN 이 막힐 수 있음 → 사진 칸 숨김)
- **처리방침**: 10절 인스타 칸 "사진은 받지 않습니다" → "행사가 나온 게시물의 대표 사진 1장을 받아 서버에 저장 · 그 행사 정보를 삭제하면 다음 동기화 때 함께 삭제" (종료된 인스타 행사는 지금 DB 에 남으므로 사진도 남음 → "지난 인스타 행사 정리 규칙"이 생기면 그때 같이 지워짐)로 바꿈 (`PrivacyPolicyPageTest`)
- **Meta 약관 3.d.i.2.a "필요 없어지면 삭제"**: 사진은 행사 행에 묶여 있어, 행사가 지워지면 사진도 지워짐. 나중에 할 일 "지난 인스타 행사 정리 규칙"을 만들면 그 규칙이 행사를 지우는 순간 사진도 따라감(따로 규칙 불필요)
- **설계 원칙 변경**: `instagram-integration.md` 1번 "사진은 복사하지 않음(저작권)" → 공식 계정(수원시 · 문화기관) 글에 한해, 행사 표시 동안만 대표 사진 1장 보관 · 출처 링크 유지로 바꿈 (11/9 사용자 결정)
- **배포**: `deploy.sh` 변경 없음 — `up -d --build` 가 새 볼륨을 만들고, Dockerfile 이 `/app/images` 를 spring 소유로 미리 만들어 둠(로그 폴더와 같은 방식). CI 가 쓰기 가능 여부를 확인
